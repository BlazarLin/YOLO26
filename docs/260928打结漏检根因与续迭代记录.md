| V6 原模型（扩充后 11 OK） | 29/29 | 28/29 | 0/11 |

## 3. 局部亮度对照：直接检验模型依赖区域

仅对验证 NG 做软件扰动；打结区域使用人工框外扩 20 像素并对边缘高斯平滑。每次保持模型、阈值与图像不变，只调整加亮位置：

| V6 输入 | 严格检出 | 相对原图匹配分数中位变化 | 分数下降超过 0.05 的图 |
| --- | ---: | ---: | ---: |
| 原图 | 28/29 | 0 | 0/29 |
| 整图 +11 | 22/29 | -0.105 | 17/29 |
| 只加亮打结框及周边 | 21/29 | -0.133 | 19/29 |
| 只加亮框外背景 | 28/29 | +0.005 | 0/29 |

这支持“模型对缺陷附近像素敏感”的判断，也解释为何整图加亮就漏检；它**不能证明**检测头学到了打结语义，因为人工干预仍可能改变边缘和局部对比度。前一轮卷积层可视化已显示早期层与 P3/P4 在耳带附近有响应，但普通正常耳带和印字也激活；特征响应不等于分类正确。[完整分层热图与遮挡对照](260928口罩打结检测迭代记录.md#6-关键层特征可视化方法)。

本轮针对两张困难 NG，再将 V6 与 V29 的 early Conv、backbone P3/P4、neck P3 输出按通道取平均并叠加到原图。以下为 [V6 的 `56s219ms` 特征汇总](../x64/output/20260928_113627/expanded/features/v6_rootcause/C1_260313_15h57m56s219ms_dajie_summary.jpg) 与 [V29 同图汇总](../x64/output/20260928_113627/expanded/features/v29_rootcause/C1_260313_15h57m56s219ms_dajie_summary.jpg)，另有 [`53s193ms` 的 V6](../x64/output/20260928_113627/expanded/features/v6_rootcause/C1_260313_15h57m53s193ms_dajie_summary.jpg) 和 [V29](../x64/output/20260928_113627/expanded/features/v29_rootcause/C1_260313_15h57m53s193ms_dajie_summary.jpg)。缺陷框内与整图平均能量比在这些层约 0.70～1.29；两模型对缺陷附近都有响应，也对正常耳带、边缘和印字响应。它排除了“该区域在中间层完全没有信号”的简单解释，但通道均值会掩盖特定通道与检测头的组合，**不能证明特征提取已经正确或直接解释某一预测框**。完整通道图及逐层数字分别在 `expanded/features/v6_rootcause/` 和 `expanded/features/v29_rootcause/`。

### 贴边漏检的四周补边对照

为检验贴边上下文，只在推理时对四周各增加图宽/高 5% 的边框，预测框映回原图；模型、640 输入、0.25 阈值不变。未补边的重复评估逐图匹配分数与原评估完全一致。

| V6 输入 | NG 严格检出 | OK 误报 | `56s219ms` 匹配框分数 |
| --- | ---: | ---: | ---: |
| 原图 | 28/29 | 0/11 | 0.010 |
| 镜像补边 5% | 26/29 | 0/11 | 0.049 |
| 固定灰度 100 补边 5% | 27/29 | 0/11 | 0.267 |

固定灰度补边修复了原先那张贴边漏检，却使 `53s193ms`、`53s569ms` 两张由检出变漏检；镜像补边没有修复原漏检，且新增同样两张漏检。这给“边界上下文影响定位/打分”提供干预证据，但不是可全局启用的优化。补边还使目标在 640 输入中变小，影响不可归因于边界内容单一因素。

把补边减至 2%，原漏检图的匹配分数升至 0.691，但 `53s193ms` 改成漏检，整集仍 28/29。仅当 V6 第一遍已有 ≥0.25 的框且该框距图像边界不足 20 像素时，才补边重跑并合并两遍框：主验证原图达到 29/29，触发 10/40 张；统一加亮仍为 22/29，翻转仍为 28/29。更关键的是，三份比例拆分的原图基线分别为 33/34、32/34、31/34，条件补边后**全部持平**，各触发约 9～10/47 张。它是针对当前单张困难图的特定修复，没有跨拆分稳定收益，不能作为正式优化。记录见 `x64/output/20260928_113627/edge_retry/`。

上下翻转增强不是“只要产线有两种朝向就应该加”的通用结论。在种子 42 中，亮度微调和双朝向微调均原图 33/34、加亮 32/34，而软件上下翻转分别为 34/34 和 33/34。种子 123 的双朝向模型虽然原图及加亮都由 32/34 升至 33/34，却在原图新增 **1/13 OK 误报**，原亮度微调模型为 0/13。误报图 `C1_260310_16h11m32s254ms.bmp` 的左上空白边角出现 0.317 分框，见 [误报叠框图](../x64/output/20260928_113627/evaluations/seed123_flipud_raw/C1_260310_16h11m32s254ms.jpg)。这提示增强会改变边界背景的打分，需要按 OK 误报共同选型。

V19 的裁图宽度为原图 60%，左右重叠；训练时跳过被裁断的正样本，避免把部分打结错误标成背景。该对照既改变目标像素大小，也改变视野和负例比例，因此不能将退化全部归于其中任一因素。所有裁图均从原训练图生成，同一原图不会跨训练/验证。

V33/V34 专门针对扩充验证集发现的“正常耳带交叉处假打结”加入训练集来源的正常裁图：原训练图 145 张、训练来源正例裁图 106 张、正常裁图 163 张；验证仍为原图 40 张，未拿验证 OK 的误报位置回灌。V34 在裁图压力测试中把 V6 的 3/11 OK 误报压到 0/11，但整图 0.25 阈值下 NG 由 28/29 降到 26/29；这属于明显的检出与误报交换，不能因为假阳性改善就替换基线。V33 在第 12 轮被监控状态 JSON 的 Windows 文件占用打断，并非模型训练异常；`python/train.py` 已对写入作短暂重试且不再让监控失败终止训练。V34 是从 V33 last.pt **重新启动优化器**的另一轮微调，不是完整恢复原训练状态。

逐图反查 V34 的三张严格漏检：`53s193ms`、`54s705ms`、`56s219ms`。对比 V6，前两张是新增漏检；它们的 V6 正确框分数 0.341、0.503，在 V34 变成 0.009、0.046，尽管 V34 仍输出 0.629、0.724 的局部高分框。原有 `56s219ms` 的完整匹配框分数从 0.010 进一步降为 0.003，高分局部框为 0.669。[`54s705ms` 的 V34 叠框](../x64/output/20260928_113627/evaluations/v34_raw/C1_260313_15h57m54s705ms_dajie.jpg)清楚显示红框只圈住耳带拐弯处，绿色人工框还包含较长横向连接段。加正常裁图后，模型更倾向局部形态却偏离了现有框选范围；仍须先人工定统一框选准则，再判断这是模型回归缺陷还是标注范围要求不合适。

V35 把正例裁图去掉，训练集只保留 145 张原图和从训练集产生的 163 张正常区域裁图；它在第 13 轮早停。整图原图为 27/29，裁图 OK 误报为 0/11，但整图加亮 11 后仅 18/29，较 V6 还少 4 张。原图漏检 `53s193ms` 与 `56s219ms`：V35 的最高分仅 0.065、0.099，连图像级有框也只剩 27/29，而 V6 是 29/29。由此可见，**误报消失并不表示只加负例是有效优化**；训练比例和局部/整图分布会压制本应保留的打结响应。V33/V34/V35 都不是部署候选。

V27 的训练终点记录 mAP50 约 0.959，高于 V23 的约 0.948，但固定业务口径下原图严格检出分别为 26/29 与 27/29。这说明仅按框平均精度选权重可能错过产线最关心的漏检图；最终比较以逐图 0.25 阈值和 IoU≥0.5 为准。

亮度训练副本只由训练图生成：每张原训练图加 -12 和 +12 两份，验证图保持原样。训练数据中 NG 和 OK 的平均灰度区间开始重叠；最佳单个平均灰度阈值在训练副本上只能达到约 81.6%，远低于原数据的 100%。仍不能代替真实跨光照图。

## 7. 下一步和量产验收条件

1. **先补同班次且两种朝向均含 OK/NG 的图。** 用户确认现有 PNG 与 NG 同机位同曝光，但它们采集日期、灰度和印字位置仍与类别分离。应在相近材料批次、同班次和每种真实朝向下同时含两类，并记录文件名、朝向、材料、设备状态；训练/验证仍按用户要求混合后按比例拆分，不按日期硬切。
2. **统一框选语义。** 明确仅框打结核心，还是必须覆盖核心、连接段和完整垂带。先人工复核 `...53s193ms` 和 `...56s219ms` 及审阅图中的大小极值，再在源数据旁另建版本，不能直接改原图/原 JSON。
3. **做多批次独立验收。** 当前 V6 的 28/29 NG 对应观测检出率 96.6%，但二项分布 Wilson 95% 区间下限约 82.8%；11 张 OK 零误报的误报率区间上限仍约 25.9%。这些区间还假设样本独立同分布，而本批图像并不满足跨班次独立性，所以更不能据此保证真实检出率 ≥90% 或产线低误报。最终要以生产节拍换算每小时 OK 张数和可接受误报上限，报告不同光照、朝向、边界位置的分层结果。
4. **保留 V6 为稳定参照。** 插值模型只在新批次、同工况数据上同时保持原图严格检出和扰动稳健性，并且没有增加误框后，才提升为可部署候选。若图像级拦截足够而缺陷提取框不够，需分开验收这两个不同目标。
5. **骨干规模与定位权重按受控实验决定。** 下面补做的冻结、YOLO26s、框距离权重对照都未同时提升原图 NG 与扰动稳健性，不应仅因网络更大或训练 mAP 较高而替换 V6。先把同班次双朝向数据和框选规范补齐，再考虑 P2 检测头或更复杂的结构改造。

逐层参数审计而非仅凭配置推断冻结生效：全网络续训的骨干参数相对 L2 变化为 0.1456；冻结层 0～10 的 11 层参数变化全部为 **0**，颈部和检测头仍分别变化约 0.1545、0.1865。JSON 原始结果：[全网络](../x64/output/20260928_153645/diagnostics/n_full_parameter_change.json)、[冻结骨干](../x64/output/20260928_153645/diagnostics/n_freeze11_parameter_change.json)。冻结保住 V6 的原图检出，却没有让那张贴边漏检图合格；全网络续训新增 `52s803ms`、`53s193ms` 两张漏检。直接加大框距离权重使 5 张 NG 严格漏检，说明现有“核心或连接段都可能被框进”的标注差异，不能靠单一损失系数补救。

### 特征图与预测框一同阅读

对同一张贴边漏检 `56s219ms` 导出了 [全网络续训](../x64/output/20260928_113627/expanded/features/n_full_backbone_audit/C1_260313_15h57m56s219ms_dajie_summary.jpg)、[冻结骨干](../x64/output/20260928_113627/expanded/features/n_freeze11_backbone_audit/C1_260313_15h57m56s219ms_dajie_summary.jpg)、[YOLO26s](../x64/output/20260928_113627/expanded/features/s_backbone_audit/C1_260313_15h57m56s219ms_dajie_summary.jpg)的 early Conv、backbone P3/P4、neck P3，另有 `53s193ms` 困难 NG 和新增 PNG OK 的对应图。冻结模型的 early Conv、P3、P4 框内/全图能量比分别为 1.119、1.105、1.078，与 V6 完全一致；颈部 P3 由 1.028 变成 1.048。YOLO26s 的相应比例为 1.115、1.087、1.060、1.048。不同模型每张热图分别按百分位着色，颜色深浅**不可作为跨模型绝对能量比较**。这些图显示各模型均在耳带和图像边界有响应，但 s 对 `56s219ms` 的完整匹配框最高分仅 0.001，高分局部框约 0.467；增加骨干通道并未解决框范围问题。

### 输入分辨率与推理代价

只改 V6 推理输入、不重训：640 为 28/29 NG、0/11 OK 误报；800 为 28/29、**1/11 OK 误报**；960 为 26/29、0/11。更大输入没有改善当前固定权重；这项测试不能代表以 800/960 重新训练的结果。当前目标框中位宽约 96 像素，缩到 640 输入仍有约 58 像素，因此先不把没有同尺寸预训练权重的 P2 结构当默认方向。

同机 RTX 3060 上，将官方预训练起点得到的 n/s 两模型同时载入，在同一张 1050×542 图上各预热 30 次，交错测 100 次：n 中位数 **14.71 ms**、P90 15.84 ms；s 中位数 **16.14 ms**、P90 17.11 ms，s 约慢 9.7%。范围包含 Python `model.predict` 的预处理、网络、后处理和框转存 CPU，不含读盘、权重加载和产线采集；[原始计时 JSON](../x64/output/20260928_153645/benchmarks/n_vs_s_interleaved.json)。不同进程单独计时的 V6 曾在 15.35～16.89 ms 波动，因此跨次绝对耗时不应当作结构差异。

**决定：仍保留 V6 的 640 整图路径。** 这批受控对照说明“骨干训练过多”和“增大骨干或输入”均没有自动改善当前漏检。优先处理人工框选语义和真实同工况双朝向样本，再用未参与选型的新批次复核；当前 29 NG、11 OK 的观测值不能保证量产达到 90% 检出与目标误报率。

- [可视化 HTML](../x64/output/20260928_113627/口罩打结根因优化可视化.html)：逐图叠框、批次散点图、标注审阅和扰动对照。
